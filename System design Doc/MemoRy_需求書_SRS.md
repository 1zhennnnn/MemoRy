## 1. 系統概述

### 1.1 目的

MemoRy 是一套以「零負擔知識採集」為核心的 AI 知識管理系統，主要透過 Chrome 瀏覽器擴充功能運作，配合網頁儀表板提供回顧與管理介面。系統整合生成式 AI（Gemma 4 E4B）、向量資料庫（pgvector）與 RAG 檢索增強生成技術，讓使用者在不改變日常瀏覽行為的前提下，自動完成知識的採集、摘要、分類與檢索。

### 1.2 名稱來源

MemoRy = **Memo**（備忘）+ **Memory**（記憶）+ **Diary**（日記）

### 1.3 系統組成

| 元件 | 說明 |
|------|------|
| Chrome Extension（MV3）| 主要使用者介面，負責知識擷取入口 |
| 即時互動側欄（Side Panel）| 低干擾式瀏覽輔助介面 |
| 後端 API 服務 | AI 處理、Embedding、RAG 查詢 |
| PostgreSQL + pgvector | 筆記資料與向量索引存儲 |
| 網頁儀表板（Web Dashboard）| 知識回顧、日報閱讀、主題聚合 |

## 2. 利害關係人與使用者

### 2.1 主要使用者

**個人知識工作者 / 學習者**
- 習慣在瀏覽器中閱讀新聞、部落格、學術文章
- 有「先存再說」行為，但缺乏有效的後續整理機制
- 希望日後能快速找回、理解曾收藏的內容

### 2.2 次要利害關係人

| 角色 | 關注點 |
|------|--------|
| 開發團隊 | 系統可維護性、AI 成本控制、技術可行性 |
| 指導教師 | 系統完整性、文件品質、成果展示 |

### 2.3 使用者特徵假設

- 使用 Chromium 系瀏覽器（Chrome / Edge）
- 具備基本電腦操作能力，非技術背景
- 每日閱讀 3～10 篇網頁文章或觀看線上資料
- 不願花費超過 30 秒進行任何手動整理動作

## 3. 功能需求

### 3.1 知識擷取（FR-CAP）

| 編號 | 需求描述 | 優先級 |
|------|---------|--------|
| FR-CAP-01 | 使用者可在任意網頁反白選取文字，透過右鍵選單一鍵儲存至 MemoRy | 高 |
| FR-CAP-02 | 使用者可在側欄貼入（Ctrl+V）或拖拉截圖，觸發圖片 OCR 流程 | 高 |
| FR-CAP-03 | 系統在擷取當下自動記錄來源 URL、頁面標題與時間戳記 | 高 |
| FR-CAP-04 | 擷取後系統立即非同步啟動 AI 摘要生成，不阻塞使用者繼續瀏覽 | 高 |
| FR-CAP-05 | 使用者可在儲存前手動補充個人心得（可選，不強制） | 中 |

### 3.2 AI 摘要與標籤生成（FR-AI）

| 編號 | 需求描述 | 優先級 |
|------|---------|--------|
| FR-AI-01 | 系統自動為每筆筆記生成 AI 標題（title） | 高 |
| FR-AI-02 | 系統自動為每筆筆記生成 AI 摘要（summary，精簡版） | 高 |
| FR-AI-03 | 系統自動生成 2～3 個語意標籤（tags），優先使用已存在標籤 | 高 |
| FR-AI-04 | 針對截圖輸入，系統使用多模態 LLM 辨識圖中所有文字並同步生成摘要 | 高 |
| FR-AI-05 | 使用者手動編輯筆記內容後，系統自動重新觸發 Embedding 向量化 | 中 |
| FR-AI-06 | AI 摘要失敗時，系統顯示錯誤提示並允許使用者手動重試 | 中 |

### 3.3 向量化與語意索引（FR-VEC）

| 編號 | 需求描述 | 優先級 |
|------|---------|--------|
| FR-VEC-01 | 每筆筆記完成摘要後自動觸發 EmbeddingGemma，生成 768 維語意向量 | 高 |
| FR-VEC-02 | 向量資料存入 PostgreSQL pgvector，建立 ivfflat 索引 | 高 |
| FR-VEC-03 | 筆記數量較少時（< 1,000 筆）使用精確搜尋（exact scan），超過後切換索引搜尋 | 中 |

### 3.4 語意搜尋與 RAG 查詢（FR-RAG）

| 編號 | 需求描述 | 優先級 |
|------|---------|--------|
| FR-RAG-01 | 使用者可在儀表板或側欄以自然語言輸入查詢 | 高 |
| FR-RAG-02 | 系統將查詢轉換為向量，以餘弦相似度比對所有筆記 | 高 |
| FR-RAG-03 | 系統召回語意相近筆記（top-K），注入 LLM 生成自然語言回答 | 高 |
| FR-RAG-04 | 回答同時顯示來源筆記卡片清單，使用者可點擊進入詳細頁 | 高 |
| FR-RAG-05 | 向量比對加入時間加權機制，近期筆記得分較高 | 中 |
| FR-RAG-06 | 支援一般關鍵字搜尋（title / summary 全文比對），作為語意搜尋的補充 | 中 |

### 3.5 笔記管理（FR-NOTE）

| 編號 | 需求描述 | 優先級 |
|------|---------|--------|
| FR-NOTE-01 | 使用者可查看所有筆記列表，支援依時間排序 | 高 |
| FR-NOTE-02 | 使用者可開啟單筆筆記的詳細頁，查看原文、摘要、標籤、來源 | 高 |
| FR-NOTE-03 | 使用者可手動編輯筆記的標題、摘要、心得與標籤 | 中 |
| FR-NOTE-04 | 使用者可刪除筆記，系統同步刪除對應向量記錄 | 中 |
| FR-NOTE-05 | 使用者可依標籤、來源網域、時間區間篩選筆記 | 中 |
| FR-NOTE-06 | 使用者可匯出所有筆記為 JSON 或 Markdown 格式 | 低 |

### 3.6 日報生成（FR-REPORT）

| 編號 | 需求描述 | 優先級 |
|------|---------|--------|
| FR-REPORT-01 | 系統每日定時生成日報，包含「今日學習要點」 | 中 |
| FR-REPORT-02 | 日報包含「跨域聯想分析」，由 AI 連結不同主題筆記 | 中 |
| FR-REPORT-03 | 日報包含「明日探索建議」 | 低 |
| FR-REPORT-04 | 日報包含開放式日記區塊，使用者可補充當下思考 | 低 |
| FR-REPORT-05 | 使用者可在儀表板以時間軸方式回顧所有日報 | 中 |

### 3.7 主題聚合（FR-CLUSTER）

| 編號 | 需求描述 | 優先級 |
|------|---------|--------|
| FR-CLUSTER-01 | 系統依語意向量相似度，自動將筆記分群為主題 | 低 |
| FR-CLUSTER-02 | 使用者可從主題維度（非時間維度）瀏覽相關筆記 | 低 |
| FR-CLUSTER-03 | 系統在閱讀某筆記時，側欄推薦語意相關的歷史筆記 | 中 |

### 3.8 帳號與資料安全（FR-AUTH）

| 編號 | 需求描述 | 優先級 |
|------|---------|--------|
| FR-AUTH-01 | 使用者以 Supabase OAuth 登入（Email / Google） | 高 |
| FR-AUTH-02 | 所有資料隔離至個人帳號，不得跨使用者存取 | 高 |
| FR-AUTH-03 | Chrome Extension 透過 chrome.identity.launchWebAuthFlow() 執行 OAuth | 高 |
| FR-AUTH-04 | Token 加密存於 chrome.storage.local，不存於 localStorage | 高 |

## 4. 非功能需求

### 4.1 效能需求（NFR-PERF）

| 編號 | 需求描述 | 目標值 |
|------|---------|--------|
| NFR-PERF-01 | 文字擷取觸發到 AI 摘要回傳時間 | ≤ 5 秒（一般網路環境） |
| NFR-PERF-02 | 截圖 OCR 完整流程（辨識 + 摘要）時間 | ≤ 10 秒 |
| NFR-PERF-03 | 語意搜尋查詢回應時間 | ≤ 3 秒（1,000 筆筆記以下） |
| NFR-PERF-04 | 側欄開啟渲染時間 | ≤ 1 秒 |

### 4.2 可靠性需求（NFR-REL）

| 編號 | 需求描述 |
|------|---------|
| NFR-REL-01 | OCR 辨識正確率 ≥ 85%（以 10 筆 Golden Set 驗收） |
| NFR-REL-02 | AI 摘要品質達標率 ≥ 80%（相關性 / 完整性 / 精簡性三維評分） |
| NFR-REL-03 | AI 失敗時系統不中斷主流程，以降級模式繼續（顯示原文，無摘要） |
| NFR-REL-04 | 截圖 CORS 失敗時自動降級至純文字模式 |

### 4.3 安全性需求（NFR-SEC）

| 編號 | 需求描述 |
|------|---------|
| NFR-SEC-01 | 資料庫使用 Supabase RLS（Row Level Security）行級安全策略 |
| NFR-SEC-02 | 所有 API 請求須攜帶有效 JWT Token |
| NFR-SEC-03 | 圖片上傳大小限制（建議 ≤ 10 MB） |
| NFR-SEC-04 | 提供完整個人資料匯出功能，確保資料自主權 |

### 4.4 可用性需求（NFR-UX）

| 編號 | 需求描述 |
|------|---------|

| NFR-UX-02 | 截圖貼入操作步驟 ≤ 3 步（開側欄 → Ctrl+V → 確認儲存） |
| NFR-UX-03 | 所有 AI 處理均非同步執行，不阻塞使用者繼續瀏覽 |
| NFR-UX-04 | 介面語言支援繁體中文 |

| NFR-COMPAT-01 | 支援 Chrome 120+ 及 Edge 120+（Chromium 核心） |

## 6. 使用情境（Use Cases）

### UC-01：文字擷取流程

```
主要參與者：使用者
前置條件：已安裝 Extension 並登入
主要流程：
  1. 使用者在任意網頁反白選取文字段落
  2. 右鍵開啟選單，點擊「儲存至 MemoRy」
  3. Extension 自動擷取：選取文字、來源 URL、頁面標題、時間戳記
  4. Side Panel 開啟（或更新），顯示「處理中」狀態
  5. 後端 API 呼叫 Gemma 4 E4B 生成 title / summary / tags
  6. Side Panel 顯示 AI 摘要結果
  7. 使用者（可選）補充個人心得後點擊「儲存」
  8. 後端觸發 EmbeddingGemma，寫入 pgvector
替代流程：
  5a. AI 摘要失敗 → 顯示錯誤提示 + 「重試」按鈕，原文仍儲存
```

### UC-02：截圖 OCR 流程

```
主要參與者：使用者
前置條件：已安裝 Extension 並登入
主要流程：
  1. 使用者對任意畫面截圖（OS 截圖工具）
  2. 開啟 Side Panel，Ctrl+V 貼入截圖（或拖拉上傳）
  3. Extension 透過 chrome.offscreen API 取得圖片 Blob，轉為 Base64
  4. 後端 API 將 Base64 圖片送至 Gemma 4 E4B（多模態）
  5. Gemma 4 E4B 執行 OCR + 語意理解 + 摘要生成（一次 API 呼叫）
  6. 回傳 JSON：{ title, recognized_text, summary, tags }
  7. Side Panel 顯示辨識文字、摘要、標籤
  8. 使用者補充心得後儲存，觸發 Embedding
替代流程：
  3a. 截圖 CORS 限制 → 自動降級，提示使用者以純文字模式輸入
  5a. OCR 信心度過低 → 顯示「辨識結果可能不完整」警告
```

### UC-03：RAG 語意搜尋

```
主要參與者：使用者
前置條件：已登入，筆記庫中有至少 1 筆筆記
主要流程：
  1. 使用者在儀表板搜尋欄輸入自然語言查詢
  2. 後端 EmbeddingGemma 將查詢轉為 768 維向量
  3. pgvector 計算查詢向量與所有筆記向量的餘弦相似度（時間加權）
  4. 取 top-K 相關筆記摘要作為 Context
  5. Gemma 4 E4B 生成自然語言回答 + 來源清單
  6. 儀表板顯示：AI 彙整回答 + 相關筆記卡片（可點擊）
替代流程：
  無相關筆記 → 回傳「目前尚無相關筆記，建議先收藏相關內容」提示
```

## 7. 系統邊界與限制

### 7.1 系統範圍內

- Chrome / Edge 瀏覽器中的文字擷取與截圖 OCR
- AI 摘要、標籤、Embedding 自動生成
- 個人筆記的 CRUD 操作
- 語意搜尋（向量）與關鍵字搜尋
- 每日日報生成
- 網頁儀表板（時間軸、主題聚合、日報回顧）

### 7.2 系統範圍外（本版本不包含）

- 手機 App（iOS / Android 原生）
- Firefox / Safari Extension（MV3 不相容）
- 多人協作 / 知識庫分享
- PDF 直接上傳解析（截圖 OCR 可替代）
- 影片內容分析（文字與圖片為主）
- 自動同步 Kindle / Readwise / Notion 等第三方平台

### 7.3 技術限制

| 限制 | 說明 |
|------|------|
| MV3 Service Worker 30 秒強制休眠 | 使用 chrome.alarms 每 25 秒自喚醒 |
| 截圖跨域 CORS | chrome.offscreen API 轉 Base64 處理 |
| Supabase Free Plan 500MB DB | 筆記量約 10 萬筆（視平均長度） |
| Gemma API 速率限制 | 批次處理與佇列機制處理高峰 |

## 8. 驗收標準

### 8.1 功能驗收

| 驗收項目 | 標準 | 測試方式 |
|---------|------|---------|
| 文字擷取 E2E | 從右鍵選取到 AI 摘要顯示完整流程可運作 | 手動測試 5 筆不同來源文字 |
| 截圖 OCR E2E | 從貼入截圖到摘要顯示完整流程可運作 | 10 筆 Golden Set 截圖 |
| RAG 搜尋 | 自然語言查詢能召回語意相關筆記並生成回答 | 5 筆查詢測試 |
| 日報生成 | 系統能正確生成包含當日筆記要點的日報 | 手動觸發日報生成 |
| 帳號隔離 | A 使用者無法看到 B 使用者的筆記 | 兩帳號交叉驗證 |

### 8.2 品質驗收

| 指標 | 目標 |
|------|------|
| OCR 辨識正確率 | ≥ 85%（10 筆 Golden Set） |
| AI 摘要品質達標率 | ≥ 80%（15 筆 Golden Set，三維評分） |
| 文字擷取回應時間 | ≤ 5 秒 |
| 截圖 OCR 回應時間 | ≤ 10 秒 |

### 8.3 里程碑驗收（Week 3 強制 E2E）

- [ ] 文字擷取流程（右鍵 → 摘要 → 儲存）完整通過
- [ ] 截圖 OCR 流程（貼入 → 辨識 → 摘要 → 儲存）完整通過
- [ ] 兩條路徑均可寫入資料庫並查詢
