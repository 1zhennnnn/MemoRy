# MemoRy — 任務拆解策略

## 1. 開發策略概述

### 核心原則

1. **API-First**：後端 API 完整可用後，前端才能平行開發
2. **最小可驗證單元**：每個 Phase 結束都能 end-to-end 手動測試
3. **AI 降級先行**：先確保資料流通，AI 失敗時系統仍可用
4. **擴充點預留**：資料結構與 API 設計已考慮 v2 功能（Realtime、WebSocket）

### 整體時間線

```
Week 1-2   Phase 0：基礎設施     ✅ 完成
Week 2-3   Phase 1：後端 API     🔄 進行中
Week 3-4   Phase 2：AI 整合
Week 4-5   Phase 3：Chrome Extension 核心
Week 5-6   Phase 4：Web Dashboard MVP
Week 6-7   Phase 5：進階功能
Week 7-8   Phase 6：品質與部署
```

## 4. 風險登記表

| # | 風險 | 影響 | 機率 | 緩解策略 |
|---|------|------|------|---------|
| R1 | Gemma API 速率限制 | AI 功能延遲 | 中 | 實作 retry with exponential backoff；批次請求 |
| R2 | pgvector 效能瓶頸 | 搜尋變慢 | 低 | 1000 筆後建 IVFFlat index；監控 query 時間 |
| R3 | Chrome MV3 限制 | Extension 功能受限 | 中 | 截圖改用 `chrome.tabs.captureVisibleTab`；大檔分塊傳輸 |
| R4 | Supabase JWT 驗證失敗 | 無法登入 | 低 | 開發模式 fallback；詳細錯誤日誌 |
| R5 | base64 圖片超過 15MB | 上傳失敗 | 低 | Extension 端壓縮圖片再上傳（canvas resize） |
| R6 | 向量 768 維儲存成本 | DB 空間不足 | 低 | 監控 DB 大小；考慮 quantization（未來） |

## 5. 定義「完成」（Definition of Done）

每個任務完成前必須通過：

- [ ] TypeScript 無型別錯誤（`pnpm run typecheck`）
- [ ] 手動 `curl` 或瀏覽器測試通過
- [ ] 錯誤情境已處理（缺欄位、無權限、資源不存在）
- [ ] 日誌使用 `req.log` / `logger`（無 `console.log`）
- [ ] 程式碼符合本文件的開發規範
